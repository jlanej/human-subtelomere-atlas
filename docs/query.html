Query tool

The command-line query tool in atlas/ looks up ends, alleles and haplogroups in the release tables and assigns new sequences to catalogue alleles. Documentation: atlas/README.md. For browsing, use the arm pages and the allele search.

subtel-atlas: query tool for the human subtelomere allele catalogue

subtel-atlas places telomeric chromosome ends of a new assembly (or pre-cut telomere-first windows, or telomeric long reads) into catalogue release v0.1, revision 2 (data/catalogue/). For every telomeric end it reports:

  • the catalogue arm;
  • the end's mosaic of CHM13 v2.0 end segments, labelled by paralog family;
  • the S5/S10/S20 terminal states;
  • the nearest structural allele (SA-<arm>-NN), with its nativity class, evidence tier and population frequency;
  • the nearest sequence haplogroup (HG-<arm>-NN), with identities;
  • whether the allele and S20 calls survive a ±500 bp shift of the telomere boundary;
  • novelty flags.

The tool runs the catalogue's own code. The package (atlas/subtel_atlas) contains the telomere caller, the window rule, the track-based mosaic and paralog-family labels (tracks.py), and the structure, allele-matching, arm and haplogroup rules. The catalogue build (pipeline/catalogue_*.py) imports them from here. Re-querying 5,981 catalogue windows reproduces every mosaic, S5/S10/S20 state, core structure and boundary-stability call in ends.tsv (tests/validation/VALIDATION.md).

The atlas is one of several concurrent catalogues of human subtelomere variation. It complements Tan et al. 2026 (bioRxiv, doi:10.64898/2026.09.03.748401; 860 haplotypes, 500 kb ends, paralogy-block haplotypes) and Guarracino et al. 2026 (bioRxiv, doi:10.64898/2026.07.10.737660). Allele, haplogroup and family IDs here are specific to catalogue v0.1 and do not correspond to the labels used in those studies.

Install

pip install "git+https://github.com/jlanej/human-subtelomere-atlas"     # or, from a checkout: pip install .
conda install -c bioconda minimap2                                      # recommended (exact catalogue computation)
subtel-atlas fetch-refs                                                 # ~40 MB into ~/.cache/subtel-atlas/v0.1

Python dependencies: mappy, numpy, pandas; pysam is optional, for BAM/CRAM input to reads. With the minimap2 executable (>= 2.24; validated with 2.31) on PATH, the alignments are computed exactly as in the catalogue build. Without it the mappy binding is used, which is an approximation (see Limits).

fetch-refs builds the reference directory:

  • CHM13 ends. The outer 500 kb of the 48 CHM13 v2.0 chromosome ends, by HTTP range reads from the public FASTA (https://human-pangenomics.s3.amazonaws.com/T2T/CHM13/assemblies/chm13v2.0.fa). --chm13 <FASTA> reads a local copy instead.
  • Catalogue files. Copied from the repository checkout, or downloaded from --catalogue-url (the repository's raw URL once published): alleles_structural.tsv, haplogroups.tsv, allele_frequencies_by_superpop.tsv, representatives.fa.gz, paralog_families.tsv and PROVENANCE.json.
  • Verification. Every file is checked against SHA-256 values shipped with the package (one per CHM13 end, and the release checksums of the catalogue files). subtel-atlas verify-refs repeats the check. Each query re-verifies the directory; --no-verify-refs skips this for custom references.

Usage

subtel-atlas query assembly.fa.gz -t 4 > ends.tsv              # every telomeric contig end of an assembly (FASTA/FASTQ, gzip ok)
subtel-atlas query assembly.fa.gz --format json -o ends.json  # + blocks, core blocks, top-3 haplogroups, frequencies, metadata
subtel-atlas query --windows tips.fa > tips.tsv               # pre-cut tip-frame windows (first base = contig tip)
subtel-atlas query assembly.fa --chm13-genome chm13v2.0.fa    # arm probes for unnamed contigs (catalogue probe rule)
subtel-atlas reads telomeric_reads.fq.gz > reads.tsv          # EXPERIMENTAL: telomeric long reads (FASTQ/FASTA, or BAM with pysam)
  • Contig mode (default). Each side of each contig is a candidate end, read in tip frame (R ends reverse-complemented). The end is reported if the catalogue telomere caller finds a clean (CCCTAA)n block of at least --min-telomere bp starting within 8 kb of the tip (default 500 bp, the Release 2 telomeric-tip definition).
  • Window length. The window is the outer 100 kb. If the telomere/subtelomere boundary s0 lies beyond 20 kb, the window is extended to ceil((s0 + 80 kb) / 5 kb) × 5 kb so that a full-length end keeps 80 kb of subtelomere; this is the catalogue rule, reported in window_extended. Coordinates (win_start, win_end) are 1-based on the contig, as in ends.tsv.
  • Windows mode (--windows). Each record is already a tip-frame window; the telomere is called on the window. Header tokens arm=20q, side=L|R and junk_len=<bp> telo_len=<bp> (a boundary from another caller) are used when present.
  • Arms. For chromosome-named contigs (chr7, chr7_MATERNAL, HG002#1#chr7), the L end is the p arm and the R end the q arm (standard orientation assumed). --arm-map supplies arms explicitly; --no-name-arms disables name parsing. For unnamed contigs, --chm13-genome (the CHM13 v2.0 FASTA or a minimap2 -x asm5 index) applies the catalogue probe rule: 10 kb probes at 250 kb and 1 Mb from the tip, so contigs of at least 520 kb for one probe and about 2 Mb for both. Without probes the arm comes from the bin-based mosaic rule and is flagged arm_inferred (see Limits).
  • -t sets threads for minimap2 and worker processes. Output is identical for any thread count, and rows follow input order.

How an end is described

  1. Boundary. s0 = outer junk + telomere, from the shared caller. Every downstream coordinate (sub_*, switches) counts from s0.
  2. Identity tracks. The subtelomere (window from s0 on) is aligned once to the 48 CHM13 ends, keeping secondary chains. For each CHM13 end, a per-base match track gives the identity over a sliding 5 kb, evaluated on a 100 bp grid anchored at the contig tip.
  3. Labels. At each grid point:
    • home if a CHM13 end of the end's own arm (or pooled group) is within 0.5 percentage points of the best identity;
    • none if no end reaches 80%;
    • otherwise the paralog family of the best end.
  4. Blocks and structure. Runs of a label form blocks. Runs shorter than 2 kb are merged into a neighbour, and boundaries are refined at base level. Blocks shorter than 10 kb are then dropped to give the core structure (e.g. PF04|home), which defines structural alleles.
  5. Fixed windows. S5/S10/S20 take the majority label over the first 5/10/20 kb: own, tie, foreign (with the family in S*_family) or none. S*_best_end keeps the single best CHM13 end.
  6. Allele. The end matches an allele when it has the same core structure and every switch lies within 10 kb of the allele's median. Several candidates: nearest medians first, then most defining ends.
  7. Haplogroup. k-mer ANI over the first 80 kb of subtelomere against the medoid of each represented haplogroup of the arm, with an alignment check against the best one.
  8. Boundary stability. Steps 3-6 are repeated with the boundary moved by -500 and +500 bp (identity tracks shifted, no re-alignment; as pipeline/catalogue_08e_boundary_stable.py).

Paralog families (paralog_families.tsv). Some CHM13 ends share long, near-identical duplicated blocks, so the single best end can flip between them with small sequence or boundary changes. Two CHM13 ends are joined into a family when, across the catalogue, they are tied (within 0.5 points) at >= 75% of the points where the less often tied of the two is tied. Release v0.1 has six multi-member families:

Any other CHM13 end is its own family, named by its arm (e.g. 12p). A family label says which shared block the sequence belongs to; S*_best_end and the block source keep the best single end, and mean_tied gives the local number of tied ends.

Nativity class (sa_nativity_class, from the matched allele):

  • native: only home (and none) blocks.
  • within_family: every non-home block carries a family that contains the end's own arm. The sequence is closer to another member's CHM13 copy of a shared block than to the own-arm copy.
  • foreign: at least one block is labelled with a family or arm that does not contain the own arm.

Interpretation guide

  • Labels are relative to CHM13. 'Foreign' telomere-adjacent sequence most resembles another CHM13 end (family). A switch is where that resemblance changes, inside shared paralogous subtelomeric sequence; it is not necessarily a structural breakpoint. The foreign fraction depends on the window: 17.4% of Release 2 ends are S20-foreign in revision 2, and other windows give other fractions (QC.md). Report the window used.
  • Family-level forms. A form such as 20q>PF04 means that the outer block belongs to the 3q/19p shared block. S20_best_end says which member it most resembles (chr3q for SA-20q-01).
  • Matched alleles. A matched structural allele means the same core block order as a catalogued allele, with every switch within 10 kb of its median. With several candidates (sa_multiple_candidates), treat the call as the set in sa_candidates. The tier is the catalogue's evidence for the allele, not for your end:
    • A: recurrent in >= 3 samples with orthogonal support, or >= 2 orthogonal lines;
    • B: recurrent only, or 2 samples with support;
    • C: all others, including singletons.
  • Boundary instability. boundary_unstable marks calls that change when the boundary moves by 500 bp. These are typically ends whose first switch is near a block-length threshold. Prefer family-level or S20 summaries for such ends.
  • Novelty flags are relative to catalogue v0.1.
    • sa_novel_*: no catalogued allele, singletons included, fits within tolerance.
    • hg_below_threshold: no represented haplogroup medoid reaches ANI 0.995. representatives.fa.gz holds medoids only for haplogroups seen in >= 3 samples, so an end of a rarer catalogued haplogroup is also reported as below threshold.
  • Haplogroups are compared by medoid. The catalogue uses UPGMA clusters; the tool compares one medoid per haplogroup, which is less precise where haplogroups are diffuse (acroP, 10q, PAR1). See hg_second_* and hg_close_second.
  • Frequencies are Release 2 haplotype-end frequencies; the samples are not a population-based sample.

Limits

  • Arm inference without names or probes uses the bin-based mosaic rule. It gives the correct catalogue group for 84% of named ends. Use --chm13-genome (the probe rule reproduces the catalogue probe calls for 600/600 tested ends) or --arm-map whenever possible.
  • Boundary sensitivity. Moving the boundary by 500 bp changes 5-6% of foreign and within-family allele calls and < 0.5% of native ones (re-aligned test, VALIDATION.md (d)). The per-end ±500 bp flags are computed from shifted tracks without re-alignment: they agree with re-aligned calls for 99.2% of ends; they catch 26 of 32 unstable ends with no false alarms, and 6 of the 574 ends they call stable changed.
  • Tied alignments. minimap2 breaks ties between equally scoring alignments using a hash of the query name. Queries are therefore named <end_id>@0, as in the catalogue build. Renaming an input can still change rare tied calls. For a given input, output is deterministic.
  • mappy backend (no minimap2 executable). Under the track method it agrees with the minimap2 backend for S20 93.0%, core structure 92.0%, structural allele 91.5% and haplogroup 100% (400 ends), and runs at about 4 s per end per thread; the CLI prints a warning. Install minimap2 for catalogue-exact results. Rows are flagged mappy_backend_approximation.
  • Read mode is experimental. It was validated only on HG002 read slices (tests/validation/reads_hg002_summary.tsv). Reads shorter than about 50 kb give partial structures, and read errors lower identities and ANI.
  • Ends with less than 500 bp of clean telomere are not reported in contig mode; --min-telomere lowers the threshold.
  • Results are versioned against catalogue v0.1 (revision 2). IDs are not stable across catalogue releases; see data/catalogue/id_history.tsv.

Python API

from subtel_atlas import query as Q
ref = Q.Reference()                                   # verified reference directory
ends = Q.contig_ends('chr20', seq)                    # or Q.window_end(name, header_comment, seq) / Q.read_end(name, seq)
records = Q.analyse(ends, ref, backend='minimap2', threads=4)

Tests and validation

  • python -m pytest tests/ runs offline in about 15 s on small fixtures (tests/fixtures, 0.34 MB). Set SUBTEL_ATLAS_REFS to a fetch-refs directory to add a comparison with ends.tsv.
  • After a catalogue rebuild, python tests/regenerate_golden.py refreshes the golden outputs.
  • The full validation is tests/validation/run_validation.py, with stages select, query, compare, loso, shift, indep, probes, reads and mappy_backend; see tests/validation/VALIDATION.md.
