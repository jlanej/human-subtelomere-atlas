Verify it yourself

Every verdict can be re-derived from public data with one command. Nothing produced by the authors is needed beyond this repository: the reads come from the public alignment files, the person's assembly windows from the public assembly FASTA (checked against the SHA-256 in data/catalogue/ends.tsv), CHM13 v2.0 from its public URL, and the thresholds from the frozen criteria file.

1. Set up

git clone https://github.com/jlanej/human-subtelomere-atlas && cd human-subtelomere-atlas
conda create -n atlas -c conda-forge -c bioconda python=3.11 samtools minimap2 mappy pysam numpy pandas scipy
conda activate atlas

Needs internet, about 1 GB of disk for CHM13 v2.0 (downloaded once into ~/.cache/subtel-atlas/replicate) and about 8 GB of RAM for the in-memory minimap2 index.

2. Pick a claim and run it

evidence/replicate_claim.sh --list                       # claims with reads, grouped by definitive tier
evidence/replicate_claim.sh 'HG002#2#chr9_MATERNAL#L'      # HG002 maternal 9p (also confirmed in the mother)
evidence/replicate_claim.sh 'HG01258|20q|SA-20q-01'        # a 1000 Genomes ONT claim
evidence/replicate_claim.sh 'control|HG00133|20p|SA-20p-10'  # a strictly native control

The script:

  1. checks that evidence/criteria_v1.json and the packaged copy hash to a89c5eaf023ed032;
  2. downloads CHM13 v2.0 and extracts its 48 chromosome ends (subtel-atlas fetch-refs, checksum-verified);
  3. builds the claim model (donor, comparator, pattern, switch) from the catalogue tables in the repository;
  4. cuts the person's end windows from the public assembly by range and checks their SHA-256;
  5. fetches the cited reads by region from the public alignment file and keeps them by read ID (samtools view -F 0x900 -N ids.txt -X URL URL.bai REGION);
  6. evaluates every read with subtel_atlas.readevidence (the module behind subtel-atlas reads-evidence): diagnostic units, switch, genome-wide anchor, integrity, verdict, concordance with the assembly switch;
  7. prints each read's published and replicated verdict, the claim verdict, and the definitive tier (own-assembly placement on all of the person's end windows);
  8. exits 0 when everything matches.

3. Look at one read without the script

Each row of reads.tsv.gz has a samtools_command. For example, the first definitive read of HG002 maternal 9p in the R10 ultra-long data:

samtools view -F 0x900 -X 'https://human-pangenomics.s3.amazonaws.com/T2T/HG002/assemblies/polishing/HG002/v1.1/mapping/ont_r10_ul_dorado/hg002v1.1_ont_r10_ul_dorado.pri.bam' 'https://human-pangenomics.s3.amazonaws.com/T2T/HG002/assemblies/polishing/HG002/v1.1/mapping/ont_r10_ul_dorado/hg002v1.1_ont_r10_ul_dorado.pri.bam.bai' 'chr9_MATERNAL:1-52422' | awk -v r='7f6d888f-4c3f-4b04-a10d-c1f1caffa110' '$1==r'

Align it to CHM13 v2.0 (minimap2 -ax map-ont -Y) and to the person's end window, or open the showcase IGV sessions (evidence/showcase/).

What replication does and does not test

  • It re-derives each published verdict from the same public reads under the same frozen thresholds. It does not re-select the reads: the cited set is every read of the claim's read set that was conclusive, consistent or contradicting. Non-informative reads cannot change a verdict and are not fetched.
  • Results depend on minimap2/mappy versions (the published run used minimap2 2.31 and mappy 2.31). Other versions can move individual alignments, and with them, rarely, a verdict near a threshold.
  • HG003/HG004 ONT reads are stored as GRCh38 CRAMs; decoding them needs a GRCh38 FASTA (--grch38).
